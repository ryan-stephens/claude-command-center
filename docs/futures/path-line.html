Ticket line: your work moves across the screen, one key per gate

The thing on screen is a piece of work, taken from your tracker. Each ticket is a card that moves left to right through the loop you already run: plan, build, answer questions, try it, ship. Every column's gate is a single key, so the whole day is arrows and a handful of letters. The chat is still there, one tab down.

How a card gets its context

Three layers go into every card. They're gathered once, shown on the new-card screen so you can change them, and handed to Claude when the session starts.

WorkspaceIts repos, team notes and run recipe. You set these once, and every card in the workspace gets them.
TicketDescription and acceptance criteria, plus comments, attachments and linked tickets if you switch them on. Pulled from Jira or Trello.
This cardAnything you add: more repos, files, links, saved notes, other cards' findings, and your own note.
→
Context packetChecked on the new-card screen, with a size for each piece. Saved on the local server under the card's name.
→
Terminal tabclaude starts in the home repo with --add-dir for each extra repo and CC_CONTROL_CARD set. A SessionStart hook fetches the packet and returns it as context, then reports the session id, which links the card.
In the appThe SDK session gets the packet directly, with the extra repos as additional directories.

Adding more later: things you add to a running card wait on it. A UserPromptSubmit hook sends them with your next message in the terminal, or the channel delivers them at once if the tab was started with it. Sessions in the app get them straight away.

Check before building: that SessionStart and UserPromptSubmit accept additionalContext as expected, and that hooks can see the claude process's environment.

Build size

  • Board and card drawer over the existing session list and its Needs you / Working / Done grouping. M
  • Ticket inbox: read-only import from Jira and Trello (API token per source), with ticket to workspace mapping. M
  • New-card screen: sources (tickets, repo library, files and links, saved notes, other cards' findings), the three-layer packet with sizes, a preview of the exact text, and launch options. M
  • Start work: save the packet, make the branch or worktree, open a Windows Terminal tab running claude with --add-dir per extra repo; a SessionStart hook fetches the packet and reports the session id. M
  • Add context later: queue on the card, delivered by a UserPromptSubmit hook with your next message, or at once through the channel. S
  • Stage tracking from hooks (Stop, Notification, PreToolUse) plus the to-do list for plan progress. M
  • Run recipes: detect from package.json / compose.yaml, edit, run as child processes, show ports. M
  • Ship: commit, push, gh pr create, post to a Slack webhook. S–M
  • Answer from the board for terminal sessions: channel permission relay (preview, dev flag). The spike exists. S

Already in cc-control: workspaces, the repo library, status grouping, the live terminal mirror, rebindable keys, the legend and ?.

What Claude Code allows: hooks are the documented, flag-free way to get events and add SessionStart context. Channels (preview, needs --dangerously-load-development-channels) can push into a terminal session and relay its approvals. Nothing can attach to a running terminal session, so the card reads it through the SDK's getSessionMessages. Per-file undo and rewind (SDK file checkpoints) only work for sessions the app runs.

Good at

  • All work in flight on one screen, stage by stage.
  • The loop's gates are single keys: a approve, t try, f fix, s ship.
  • Ticket to PR without retyping context, and the PR body comes from the ticket.
  • Reads like Jira or Trello, so leads and non-developers follow it at once.
  • A stuck session is visible as a card that stopped moving.

Trade-offs

  • The columns assume one loop. Other teams need editable stages, which adds settings.
  • How Claude got somewhere is one level down, in the drawer.
  • Terminal sessions are followed through hooks. Answering them from the board needs the channel (dev flag) or a jump to the terminal.
  • Ticket import means Jira and Trello credentials on your machine.
  • Seven columns get tight on a laptop. Inbox and Done may need to collapse.

Drops

  • The chat-first session view as home. The transcript is a tab.
  • The number pad of commands.
  • Per-message detail and in-app modes on the main screen.
  • Sessions with no ticket appear in an "Unticketed" row, which is second class.
