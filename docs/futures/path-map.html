What Claude knows is the thing you manage

Each workspace becomes a map. Its shared context sits in the middle and its sessions sit around it. Every ticket, repo, note and finding you hand a session is drawn as a line, so you can see what each session was told and move context around with a drag.

A day with it

  1. 08:50

    You open the Storefront map. Three sessions sit around the shared hub. SHOP-142 reads 71% and its node says hand off soon.

  2. 09:00

    You drag SHOP-155 from the Jira shelf onto New session and pick Open in a terminal. A terminal opens in web-app. A SessionStart hook gives Claude the workspace notes, the three repos, the run recipe and the ticket. The map shows that packet: 2.6k tokens.

  3. 09:05

    Claude plans in the terminal, as it always has. The node's status line reads Planning. The ticket touches the cart badge, so you drag the design-tokens README onto it. The channel hands it to Claude before its next message.

  4. 10:20

    SHOP-142 passes 75%. You press h. A new node appears with a handoff summary, carrying the two items you pinned. The old one dims. You carry on in the new terminal.

  5. 11:10

    SHOP-151 says Ready to try. You press r. The web-app recipe, detected from package.json, runs install, seed and dev, and opens localhost:5173. Images still stall on a phone-sized window.

  6. 11:30

    You type the fix you want in its terminal. Its finding, "images are served by cdn-worker", shows up on the shelf. You press @ on SHOP-142 and pull it in, because the gift card thumbnail uses the same path.

  7. 14:00

    SHOP-151 works on the second round. Claude pushes and opens the PR from the terminal. The hub note tells it the review channel, so it posts to #storefront-reviews. The node moves to In review.

  8. 16:30

    You press w and add a workspace note: "Never log a full gift card code." Every new Storefront session starts with it. Running ones get it through the channel.

Good at

  • You can see exactly what each session was told, and which part came from the workspace.
  • Context moves with a drag: tickets, repos, notes, and findings from other sessions.
  • Handoffs happen before memory fills, and pinned items come along.
  • Conventions written once per workspace reach every session.
  • A non-developer can read "What Claude knows" in plain words.

Trade-offs

  • A map takes room. Past about six sessions a workspace starts to crowd.
  • Token sizes are estimates until the session reports its usage.
  • Adding to a running terminal session needs the channel, which is a preview behind a dev flag. Without it, additions wait for the next start.
  • "Context" is a new idea for newcomers. The map teaches it, but it is one more thing to learn.

Drops

  • The step-by-step timeline. Each node has one status line.
  • Chat. You talk to Claude in the terminal, or in the app's session pane as today.
  • Diff review and undo are out of view. Push, PR and the review post happen through Claude, guided by workspace notes.
